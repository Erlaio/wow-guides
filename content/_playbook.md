# WoW Guide Playbook

Процесс создания и аудита гайдов по спекам, чтобы в любой сессии получить тот же результат.
Это человеко-читаемая версия; автоматический запуск - скилл `/wow-guide create <класс> <спек>`
или `/wow-guide audit <класс> <спек>` (`C:\Users\Erlaio\.claude\skills\wow-guide\`).

Контент гайдов - на русском, названия способностей в формате `Русское (English)`, статы - English.

## Фундамент (всегда, оба режима)

1. **Зафиксировать патч.** Не предполагать - открыть Wowhead и подтвердить текущий retail-патч
   (сейчас гайды под Midnight 12.0.5). Любая проверка дальше - "верно ли это *для этого патча*".
2. **RU-имена только с Wowhead по spell ID.** EN -> spell ID через поиск Wowhead, затем
   `nether.wowhead.com/tooltip/spell/{id}?dataEnv=1&locale=7` (`name` = русское имя, описание в
   `<div class="q">`). `dataEnv=1` = retail, `locale=7` = русский (locale=8 = португальский, ловушка).
   Сверять EN<->RU по `/spell=ID` и `/ru/spell=ID`. Не выдумывать.
3. **Сверка талантов с живым деревом.** Резолв spell ID в тултипе НЕ значит, что талант ещё в игре -
   удалённые таланты (Rune Tap, Feline Potential, Eye of Tyr, Savage Momentum) висят как мёртвые
   спелл-стабы. Источник истины - data-файл калькулятора:
   `nether.wowhead.com/data/talents-dragonflight` -> payload `.trees` (type 1 класс, 2 спек, 3 hero) и
   `.abilities`. Точный парсер и классификация - в reference скилла `talent-tree-extraction.md`.
   Каждый термин: в дереве / baseline / в описании другого таланта (бафф/прок) / hero-древо / suspect.
4. **Топ-логи - практическая правда, но с оговоркой.** Страницы рейтингов WCL грузятся
   (`/zone/rankings/47?class=...&spec=...&leaderboards=1`; зона 47 = M+ S1, 46 = рейд). Скрейп-эндпоинты
   (`fights-and-participants` и пр.) теперь закрыты ("используйте API"). Для cast-последовательностей
   нужен официальный WCL API (ключ). Что нельзя подтвердить - помечать как гипотезу, не утверждать.
5. **Правила вёрстки волта.** Только ASCII-дефис (никаких `U+2013`/`U+2014`). В таблицах экранировать
   пайп в ссылках: `[[target\|alias]]`. Ссылки - `[[glossary#^anchor|Текст]]`, записи глоссария
   заканчиваются на `^anchor`. Frontmatter: `tags`, `created`.

## Режим create (новый гайд)

1. Собрать факты с method.gg / Wowhead-гайда (playwright): таланты, статы, тринкеты, гир, опенер,
   ротация, hero-древо.
2. Сверить таланты с деревом (п.3) - оставить только живые.
3. RU-имена для всех способностей (п.2).
4. Перевести гир/тринкеты/энчанты/гемы/расходники/боссов в `Русское (English)`.
5. Глоссарий: описания из официальных тултипов Wowhead, затем очеловечить (на "ты", убрать
   формульный шум, оставить смысл и практическое "почему").
6. Сверить с топ-логами (п.4): мета hero-древо, тринкеты, порядок статов, что реально берут топы;
   внести правки, пометить непроверенное.
7. Написать гайд по фиксированной структуре (ниже). Нейтральные ярлыки, без вины/стыда, без указания
   источников в тексте.
8. Обновить `index.md`, прогнать self-check.

## Режим audit (проверка существующего)

1. Собрать названия способностей из глоссария класса и всех файлов гайда спека (форматы разные:
   `**RU** (EN)` у новых, `**EN** - desc` у старых).
2. Классифицировать против дерева (п.3).
3. Suspect = удалённый/переименованный талант: найти в дереве актуальную замену по роли, подтвердить
   тултипом.
4. Починить: заменить/убрать устаревшее в глоссарии и в КАЖДОЙ ссылке гайда (включая `^anchor`).
   Перегрепнуть папку WoW на старый якорь - битых ссылок 0.
5. Проверить полноту, не только корректность: танк-гайд без раздела про урон неполон (урон = угроза +
   скорость ключа). Убедиться, что разобрана урон-механика hero-древа; добить недостающее по тултипам.
6. Перепроверить изменённые RU-имена (п.2), составить отчёт (что нашли/починили, что не проверить).

## Фиксированная структура гайда

Главное за минуту (чек-лист 5) -> Как играть (модель + словарик) -> Что изменилось в патче ->
Сильные/слабые -> Таланты (hero-развилка + строки импорта) -> Опенер + Ротация -> Урон (механика
hero-древа, в т.ч. для танков) -> Дефенсивы/митигация -> Гир/Статы/Энчанты/Расходники ->
Частые ошибки (как диагностика) -> Напоследок (одна тёплая строка, без повторного чек-листа).

"Частые ошибки" и "Напоследок" держать разными - раньше один набор пунктов повторялся трижды.

## Найденные этим процессом устаревшие записи (история)

Rune Tap (Blood DK), Feline Potential (Guardian), Eye of Tyr + Moment of Glory (Prot Pal),
Savage Momentum (Feral). Все - живые spell-стабы, но не таланты в 12.0.5.
